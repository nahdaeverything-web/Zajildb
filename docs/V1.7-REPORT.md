> "Do not fix the backlog item-by-item. The backlog's medium findings are symptoms

> caller through them, and add guard tests so a FUTURE view cannot reintroduce the

## Phase by phase

### Phase 0 — capture what already existed
`ea24281` · 19 files, +1123

The browser suites existed only as ad-hoc scripts. Located and moved into
`tests/e2e/` with a runner (`run_all.py`) and a README, plus 6 diagnostic
scripts — including the ones used to actually diagnose the scroll bug.

Moved essentially verbatim, per instruction. The only edit was making the base
URL overridable via `ZAJIL_URL`.

**Found 123 assertions across 11 suites**, not the 72 across 8 the brief
estimated.

### Phase 1.1 — local dates
`3c79b9d` · tests 33 → 41

`js/dates.js`: `todayISO(at = new Date())` takes an injectable instant so tests
need no clock control; `parseLocalDate()` keeps a bare date on its own calendar
day while leaving datetimes with real instant semantics (a race arrival time
*is* a moment).

Routed: `i18n.js` `fmtGregorian`/`fmtHijri`, `breeding.js` (pairing date, egg
laid, hatch, wean), `health.js`, `tools.js` (export filename).

### Phase 1.2 — validation at the write boundary
`1dae8f7` · tests 41 → 49

`saveBird()` now runs `classifySave()` and throws `ValidationError`. The
decision logic is pure and lives in `js/engine/validate.js`, so node can test it
without IndexedDB and the engine stays free of DOM/db/i18n.

**Strict by default:** unconfirmed warnings block the write too, so a future
view that forgets to confirm a duplicate ring cannot silently create one.
`{allowWarnings:true}` is the caller stating the user confirmed;
`{force:true}` is imports only.

Views now use `db.js` `checkBird()` for pre-flight — the same single
implementation, reached through the boundary module. No view references
`validateBird` any more.

### Phase 1.3 — change events and re-render
`2f9c86d` · Media restore moved behind `db.restoreMedia()`, which emits. No view
touches `idbPut`/`idbDelete`.

The router now refreshes on data change, with three deliberate guards because a
blunt re-render would reintroduce the v1.5 "page jumps to the top" bug:

1. **Deferred while a dialog is open** — runs when the last one closes.
2. **Skipped on form routes** — re-rendering would discard typed input.
3. **Coalesced and scroll-preserving** — a write loop causes one re-route.

`tests/e2e/change_events.py` includes the explicit regression guard requested:
a change event fired while a dialog is open leaves the dialog standing and does
not move the page.

### Phase 1.4 — referential integrity
`d6cc5ea` · tests 49 → 59

`js/engine/integrity.js` — `checkIntegrity(stores)`, pure, accepts arrays or
Maps, returns i18n keys + params. A null parent is unknown ancestry, not a
dangling reference; a whole-loft health event legitimately has no bird.

`deleteBird` now cascades and snapshots everything it touched (snapshotting
*before* mutating) so `restoreBird` puts the entire picture back.

Also surfaced in the dev panel so it is usable, not only testable.

### Phase 1.5 — one record factory
`a932606` · tests 59 → 65

`newBird()` derives both directions: `external:true` implies `REFERENCE_STATUS`,
and asking for `REFERENCE_STATUS` implies external. Derived **after** the spread,
so a caller cannot contradict it by omission. The three call sites needed no
change — they inherit it.

add-sibling now carries an **intent** (`#/bird/new?siblingOf=<id>`) and the form
commits everything only on a successful save, with a notice saying so.
Abandoning the form now writes nothing.

### Phase 2 — the guard tests
`37a2a3e` · tests 65 → 75

Source scans, **each proven to fire** by deliberately introducing the violation:

- a UTC date slice outside `js/dates.js`
- `idbPut`/`idbDelete`/`idbClear` outside `js/db.js` (reads stay allowed)
- `validateBird` called from `js/views/`
- the engine importing db/i18n/ui or touching `document`/`window`/`indexedDB`
- an i18n key missing either language
- `[dir="rtl"]` box-model overrides in CSS
- a `sw.js` SHELL entry that doesn't exist, **or any app module missing from it**

Failures name `file:line`.

Plus **data-level invariants** rather than unreliable scans — object literals
building bird records aren't detectable in text, so these build records through
the real factory and assert the property, and assert the shipped datasets
satisfy both that and `checkIntegrity`.

> **The precache guard immediately earned its keep:** `js/dates.js` and
> `js/engine/integrity.js` had not been added to the SHELL list, which would
> have broken offline for anyone who had installed the app.

### Phase 3 — import atomicity
`a5e2e79` · `importAll` now decodes and validates the entire payload — shape,
bird ids, every media blob — **before touching anything**, and takes a
`pre-import` snapshot into `backups` before a replace.

While there: `exportAll` gained `{includeMedia}`, so `autoBackup` stops
base64-encoding every photo twice a day only to discard the result.

`sw.js` bumped to `zajil-v1.7.0`.

## Decisions for you — reported, not taken

### 1. A data migration exists
`newBird()` guarantees `external === (status === REFERENCE_STATUS)`, and both
shipped datasets were regenerated to match. But `importAll` is the force path, so
**a pre-v1.7 export still imports external birds carrying `status: 'stock'`.**

Not normalised, because that changes user data. Four options in
`docs/V1.7-NOTES.md`: normalise silently; normalise and report; add a "repair
data" action in Tools; or leave it.

### 2. Strict-by-default warnings
The brief said a duplicate ring must be refused by `saveBird` itself — but a
duplicate ring is deliberately a *warning* (re-ringed birds are real).
Strict-by-default reconciles those. One line in `classifySave` if you want
warnings never to block.

### 3. `getBird` is synchronous, and the engine depends on it
The single biggest constraint on any future server-backed layer. COI traversal
calls it thousands of times inside recursive memoised paths. The fork:

- keep a full local mirror and sync it — engine untouched, and what local-first
  already implies; **strongly preferable**, or
- make the engine async, which makes `coi.js` substantially harder.

Cheapest to decide *before* building on top. Five more structural frictions are
in the notes (device-clock `updatedAt`, client-generated ids, `importAll`'s
all-or-nothing shape, payload-free change events, unenforced `loftId`).

### 4. One guard is narrower than its name
"No view writes to IndexedDB" scans for the identifiers, so
`(await import('./db.js'))['idb'+'Put']` would slip through. Every broader
pattern also matched db.js's own internals and would have had to be **loosened
to pass** — reported rather than loosened, as instructed.
